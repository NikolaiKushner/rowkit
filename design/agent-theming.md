# Темы через агента — план

7 октября 2026. Сценарий: разработчик ставит `rowkit` из npm в **свой** проект и просит своего агента (Claude Code, Cursor, Copilot…) «сделай тему в цветах нашего бренда». Наш репозиторий агент не видит: у него есть только проект пользователя, `node_modules`, терминал и, может быть, интернет. Всё, что ему нужно, должно приходить **с npm-пакетом** или с сайта.

Цель: агент без человека делает рабочую тему, подключает её в проект и сам проверяет — имена токенов, контраст WCAG AA, вид.

Делаем по шагам, после каждого — отчёт.

## Что у агента есть сейчас

- `node_modules/rowkit/AGENTS.md` — API компонентов и установка. О темах — ничего.
- `defineTheme` есть только в `@rowkit/tokens`. Это зависимость `rowkit`, но с pnpm (строгий `node_modules`) импортировать её из проекта нельзя, пока пользователь сам не поставит `@rowkit/tokens` — и тогда версии могут разъехаться.
- Правила контраста живут только в наших тестах — в пакет не попадают.
- Сам агент про `node_modules/rowkit/AGENTS.md` не знает: туда никто не заглядывает без подсказки.

## Шаг 1. Агент находит инструкцию

- [ ] Первая строка в README и на странице Installation: «Если работаете с агентом — добавьте в свой AGENTS.md / CLAUDE.md: _For rowkit, read `node_modules/rowkit/AGENTS.md`_». Готовый текст для копирования.
- [ ] `llms.txt` на сайте: ссылки на AGENTS.md и раздел о темах — для агента, который ищет в интернете.
- [ ] (Позже, после шага 3) `npx rowkit init` дописывает эту строку в AGENTS.md / CLAUDE.md проекта сам — со спросом.

## Шаг 2. Всё для темы — в пакете `rowkit`

- [ ] Новый вход `rowkit/theme`: `defineTheme`, `checkTheme`, список токенов с описаниями. Пользователь ставит только `rowkit`, версия токенов всегда совпадает с компонентами. `@rowkit/tokens` остаётся для тех, кому нужны только токены.
- [ ] Описание каждого токена хранится **в коде** (рядом со значением в `color.ts`, `size.ts`, `style.ts`, `shadow.ts`) и попадает в пакет. Из этих же данных собираются сайт и AGENTS.md — расходиться нечему.
- [ ] Полная документация токенов на сайте (вместе с шагом 7 из [integration.md](./integration.md)). Страница Tokens уже рисуется из пакета, но показывает не всё:
  - [ ] размеры компонентов (`size.ts`, `--spacing-*` вроде `toast-pl`, `chip-px`) — сейчас только общая шкала;
  - [ ] стиль-переключатели `--rk-*` — сейчас только ручная таблица на Themes, уже устаревшая;
  - [ ] значения во всех трёх темах (Windows 98, Modern Light, Modern Dark) рядом, а не только в одной;
  - [ ] описание каждого токена (из кода) и поиск по имени;
  - [ ] группировка «по компонентам»: открыл Toast — видишь все его токены;
  - [ ] таблицу «What you can change» на Themes тоже генерировать из данных, а не писать руками.

## Шаг 3. Раздел «Theming» в `node_modules/rowkit/AGENTS.md`

Генерируется `generate-agents.mjs` из данных шага 2. Написан для агента в **чужом** проекте:

- [ ] Рецепт по шагам: создать файл темы (где — по типу проекта: Vite, Nuxt), `defineTheme` из `rowkit/theme`, как подключить CSS, поставить `data-theme` на `<html>`, dark-схема.
- [ ] Как выбрать базу: `modern` для своего бренда, `win98` для ретро.
- [ ] С чего начать: 10–15 токенов, которые дают «тему бренда» (акцент, выделение, фокус, ссылки, радиусы, шрифт). Остальное — по запросу.
- [ ] Полный список токенов по группам: имя, что меняет, значения в обеих темах.
- [ ] Правила контраста и как их чинить («затемни фон, а не осветляй текст»).
- [ ] Чего не делать: переопределять классы компонентов, `dark:`, править `node_modules`.
- [ ] Последний пункт рецепта: «запусти `npx rowkit theme check` и исправляй, пока не пройдёт».
- [ ] Тест: раздел соответствует токенам (как сейчас для компонентов).

## Шаг 4. Проверка в проекте пользователя

- [ ] `checkTheme(vars, { extends })` в `rowkit/theme`: неизвестный токен, контраст ниже порога (пара, значение, нужное), значение не того вида.
- [ ] Правила контраста переезжают из `contrast.test.ts` в код пакета; наши тесты вызывают тот же `checkTheme`.
- [ ] Команда `npx rowkit theme check [файл]` — `bin` в пакете `rowkit`, ничего ставить не надо. Принимает готовый CSS темы (так не важно, написан он `defineTheme` или руками) или файл с `defineTheme`. Вывод — понятный текст, код выхода ≠ 0 при ошибках.
- [ ] Подсказка с исправлением: «`control-primary` #6a8cff × `control-primary-foreground` #fff = 3.1:1, нужно 4.5:1; подойдёт #4a6cdf».
- [ ] Тесты на функцию и команду.

## Шаг 5. Агент видит результат

- [ ] `npx rowkit theme preview [файл]` — HTML-страница с набором компонентов в теме (light и dark), открывается в браузере. Агент с браузером делает скриншот, без браузера — человек смотрит сам.
- [ ] Раздел в AGENTS.md: «после проверки покажи пользователю превью».

## Шаг 6. Проверка на настоящем проекте

Чистый Vite + Vue проект **вне** нашего репозитория, `rowkit` из упакованного tarball (`pnpm pack`), как у пользователя.

- [ ] Агенту — только запрос «сделай тему в цветах бренда #…». Без подсказок от нас.
- [ ] Записать, где он ошибся или застрял; поправить AGENTS.md / команды; повторить.
- [ ] Нарочно непохожая тема («брутализм», «Material») — чтобы найти значения, зашитые в классы компонентов (например, `gap-1` у чипа, `rounded-lg` у панели фильтров), и вынести их в токены. Windows 98 при этом не меняется ни на пиксель.

## Шаг 7. Сайт

- [ ] Страница Themes: блок «Попросите агента» — готовый текст запроса.
- [ ] ThemeBuilder показывает результат `checkTheme`.

## Потом, если понадобится. MCP-сервер

Отдельный пакет `@rowkit/mcp`, обёртка над тем же кодом: `list_tokens`, `define_theme`, `check_theme`, `preview_theme` (картинка). Даёт агенту картинку без браузера, но пользователю надо его настроить. Решаем после шага 6 — если агенту не хватило текста, команды и превью.

## Открытые вопросы

- Цвета через `color-mix()` и `var()` нельзя посчитать без браузера: требовать в теме hex или считать в headless-браузере?
- Читать файл с `defineTheme` из TypeScript-проекта без сборки — нужен загрузчик TS в команде, или достаточно CSS?
- `npx rowkit init` — правит файлы пользователя; что именно он может трогать.
