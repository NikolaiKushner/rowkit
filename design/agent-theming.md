# Темы через агента — план

7 октября 2026. Цель: пользователь rowkit говорит своему агенту «сделай тему в цветах нашего бренда» (или «строже», «плотнее», «как у Linear»), и агент делает рабочую тему без человека. Тема проходит те же проверки, что наши: имена токенов, контраст WCAG AA.

Порядок: сначала то, что работает у всех без настройки (AGENTS.md, команда в терминале), MCP — последним и только если понадобится. Делаем по шагам, после каждого — отчёт.

**Зависимость:** шаг 7 из [integration.md](./integration.md) (документация по токенам). Без полного списка токенов агенту не из чего выбирать, поэтому шаг 0 ниже делается вместе с ним.

## Что уже есть

- `defineTheme({ name, extends, light, dark })` в `@rowkit/tokens`: проверяет имена токенов, наследует базовую тему, пишет light и dark.
- `packages/ui/AGENTS.md` собирается `generate-agents.mjs` (`pnpm docs:agents`) и уходит в npm-пакет; копия — `docs/agents.md`. Раздела о темах в нём нет.
- Правила контраста живут только в тестах: `packages/tokens/src/contrast.test.ts`.
- ThemeBuilder на странице Themes (акцент, углы, плотность, шрифт).

## Шаг 0. Токены описаны полностью

- [ ] Таблица «What you can change» (`docs/foundations/themes.md`) и страница Tokens — все 293 переменные, включая добавленные при интеграции дизайна (chip, pager, toast, dialog, empty, footer-direction…).
- [ ] Описание у каждого токена хранится **в коде** (рядом со значением в `color.ts`, `size.ts`, `style.ts`, `shadow.ts`), а не только в markdown. Тогда и документация, и AGENTS.md, и команда проверки берут его из одного места и не расходятся.
- [ ] Токены компонентов сгруппированы по компонентам: что меняет каждый.

## Шаг 1. Раздел «Theming» в AGENTS.md

Генерируется тем же `generate-agents.mjs` из данных токенов.

- [ ] Рецепт: где положить файл темы, `defineTheme`, как подключить CSS, как переключить (`data-theme`, `data-color-scheme`).
- [ ] Как выбрать базу: `modern` для своего бренда, `win98` для ретро.
- [ ] Минимальный набор для «темы в цветах бренда» — какие 10–15 токенов менять в первую очередь (акцент, выделение, фокус, ссылки, радиусы, шрифт).
- [ ] Полный список токенов по группам с описанием и значениями обеих тем.
- [ ] Правила контраста: какие пары, какой порог, как чинить («затемни фон, а не осветляй текст»).
- [ ] Типичные ошибки: переопределять классы компонентов вместо токенов, `dark:`, забыть dark-схему.
- [ ] Последний шаг рецепта: «запусти проверку (шаг 2) и исправляй, пока не пройдёт».
- [ ] Тест: раздел в AGENTS.md соответствует токенам (как сейчас для компонентов).

## Шаг 2. Проверка темы

- [ ] `checkTheme(vars, { extends })` в `@rowkit/tokens`: возвращает список проблем — неизвестный токен, контраст ниже порога (пара, значение, нужное), значение не того вида (цвет в размере и т.п.).
- [ ] Правила контраста переезжают из `contrast.test.ts` в код пакета; наш тест вызывает `checkTheme` для своих тем. Одни правила — для нас и для пользователей.
- [ ] Команда в терминале: `npx rowkit theme check <файл>` — первый `bin` в пакете. Вывод — понятный текст и ненулевой код выхода при ошибках, чтобы агент видел, что не так.
- [ ] Ошибки контраста с подсказкой: «`control-primary` #6a8cff × `control-primary-foreground` #fff = 3.1:1, нужно 4.5:1; подойдёт #4a6cdf».
- [ ] Тесты на `checkTheme` и на команду.

## Шаг 3. Третья тема — проверка, что системы хватает

Нарочно непохожая на обе наши тема в Storybook (только для тестов, не публикуется). Её **делает агент по AGENTS.md**, не мы — заодно проверка шагов 1–2.

- [ ] Найти, что в ней не поменялось: значения, зашитые в классы компонентов (например, `gap-1` у чипа, `rounded-lg` у панели фильтров).
- [ ] Вынести найденное в токены (Windows 98 — ни на пиксель, проверяем pixel-diff).
- [ ] Записать, что агенту было непонятно, и поправить раздел в AGENTS.md.

## Шаг 4. Сайт

- [ ] Страница Themes: блок «Попросите агента» — готовый текст запроса и ссылка на раздел.
- [ ] ThemeBuilder показывает результат `checkTheme` (контраст выбранного акцента).

## Шаг 5 (потом, если понадобится). MCP-сервер

Отдельный пакет, например `@rowkit/mcp`. Тонкая обёртка над тем же кодом, своих правил нет.

- `list_tokens` — токены с описанием и значениями;
- `define_theme` — CSS по значениям;
- `check_theme` — то же, что `checkTheme`;
- `preview_theme` — картинка: набор компонентов в теме. Это единственное, чего нет в шагах 1–2: агент **видит** результат.

Минусы: ещё один пакет выпускать вместе с библиотекой; у пользователя должен быть настроен MCP. Решаем после шагов 1–3, по тому, хватит ли агенту текста и проверки.

## Открытые вопросы

- Имя команды: `npx rowkit theme check` (bin в пакете `rowkit`) или отдельный пакет `@rowkit/cli`.
- Где агент держит файл темы по умолчанию (`src/theme.ts`?) и как он подключается в Vite / Nuxt — рецепт для обоих.
- Нужен ли `checkTheme` проверке цветов из `color-mix()` (их нельзя посчитать без браузера) — или требовать в теме готовые hex.
